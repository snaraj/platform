## Artifact evidence and bounded dispositions

The three Flux image signatures were verified with the GitHub OIDC issuer,
their exact component repository and release-tag certificate constraints, and
the upstream reusable signer
`https://github.com/fluxcd/gha-workflows/.github/workflows/controller-release.yaml@refs/tags/v0.17.0`.
Their provenance source revisions agree with the respective upstream release
sources. Build metadata comes from the extracted ARM64 binaries, not a `go.mod`
compiler declaration. The controller export is generated by the independently
checksum-verified Flux 2.10.0 Linux AMD64 CLI.

Fresh all-severity image scans retain all findings without ignore rules. Each
Flux ARM64 image has no reported OS-package findings and three module matches:
GO-2026-5932 and the two `x/net/html` advisories GO-2026-6860/GO-2026-6866.
Binary symbol analysis excludes the affected unmaintained
`golang.org/x/crypto/openpgp` package; the separately named ProtonMail fork is
not that package. Only `html.init`, without the affected parser or renderer,
is linked into the Flux binaries. The cloudflared binary contains neither
affected package's functions. These are exact-artifact dispositions, not
global module exclusions or claims that the library versions are patched.

The Go database snapshot predates the October 30
[go-jose advisories](https://github.com/go-jose/go-jose/security/advisories),
so those original advisories are assessed separately. The selected products
still contain go-jose 4.1.6; the advisory patch floor is 4.1.7. Flux lacks the
affected JWE and JSON multi-signature parser functions. Cloudflared's Access
JWT middleware reaches the JSON-capable parser through `go-oidc` before it
rejects multiple signatures. This condition remains unresolved wherever that
middleware accepts attacker-controlled assertions.

Linked JOSE `Thumbprint` methods alone do not establish a call. Direct ARM64
call-edge inspection found only internal helper/self edges, and the inspected
Flux JWK parser rejects RSA keys and does not call `Thumbprint`. This analysis
does not prove all indirect/interface/reflection paths unreachable. Likewise,
the inspected claims-decoding types do not have the embedded-type prerequisite
of GHSA-27pc-rm86-68pq; that statement is limited to those callers.

Source-controller also links the ACR helper covered by GO-2026-6225. Its
credential-exfiltration condition requires usable Azure credentials and a
selected registry matching the vulnerable hostname expression. Anonymous
sources alone do not justify a universal closure: verify the selected source
URLs, provider modes and credential prerequisites in each deployment.

## Core containerd repairs and rollout limits

The [original containerd advisories](https://github.com/containerd/containerd/security/advisories)
distinguish malformed-digest panic, unbounded layer streams, OCI graph
amplification, repeated whiteouts, ExecSync drain, concurrent-fetch
Content-Length handling and checkpoint restore/cleanup conditions. Version
2.3.7 includes the assessed core fixes. Unsafe experimental checkpoint restore
must remain disabled; explicitly re-enabling it is not a repair.

For older 2.3.3 installations, missing `enable_criu` or
`enable_experimental_restore_via_create` settings do not prove restore is
disabled: that source has no such gates and recognizes checkpoint input during
container creation. A zero effective concurrent-layer-fetch buffer rules out
that specific concurrent-fetch prerequisite, not the other image-input paths.
Bind any configuration disposition to the active executable and config file.

A bounded, network-disabled source regression used one valid and three malformed
synthetic referrer digests. Version 2.3.3 passed the valid control and panicked
on all three malformed inputs; 2.3.7 passed all four cases. Both source tests
used the same Go 1.27.3 compiler. This isolates the core source repair; it does
not change the separate Go 1.26.9 metadata of the published runtime binary.

Before a rollout, independently verify the protected source release, exact
candidate and rollback artifacts, current target identity and recovery access.
Exercise Flux startup and anonymous Git/signed OCI/application reconciliation
in a disposable environment with the existing narrow roles. Wrong signer,
digest, cross-namespace reference and unauthorized tenant operations must fail.
Do not add Secret list/watch, token creation or broader controller authority to
make the upgrade pass. Preserve the existing host binary launcher's stop;
source pin changes do not authorize bypassing it. No CRD deletion, storage
migration, credential change or new route is part of this repair.

After a scoped deployment, correlate the reviewed commit, authenticated
release, selected revision, actual running digests and application behavior.
Keep the remaining Go/JOSE conditions open independently of successful core
repairs. No source or scanner result is a live delivery receipt.
